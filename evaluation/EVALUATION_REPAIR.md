# Benchmark scoring integration

The QUEST answers are scored with the benchmark evaluators and original task data; changing the judge model to DeepSeek Flash means scores are not necessarily comparable to official leaderboard scores.

For DeepResearch Bench, download the official `data/test_data/cleaned_data/reference.jsonl` from https://github.com/Ayanami0730/deep_research_bench into a separate data directory, and set `DRB_REFERENCE_FILE` to its absolute path. The reference used in the 2026-10-28 repair has SHA-256 `0d7887990f4c1c20aee2ffdd46b58543767efbf7bb8faf35799954ac4adbc802`. `run_drb_eval.sh` selects the original query metadata for the actual input prompts and keeps cleaned data and logs under `OUTPUT_DIR`. Its RACE and FACT scores remain separate. FACT reports null when no citation can be evaluated. A Jina key is needed for FACT, not for RACE alone.

For Mind2Web2 the adapted evaluator in the current run uses `MIND2WEB_HEADLESS=1` with the installed Playwright Chromium and shared libraries. Preserve its verification logs: a tool/browser error can be converted into a zero by the upstream task scripts, so an exit code or final score alone does not establish validity.

`score_receipts.py` checks native artifacts before labeling a result scored. For WideSearch an unparseable response is retained as the official evaluator's zero and labeled as a format failure. BrowseComp+ answer correctness is separate from retrieval and citation metrics; the current QUEST adapter does not record the required document IDs. LiveResearchBench depth requires its official reference report: an unavailable report must be marked missing, never replaced with an invented reference.

The current repair writes independent artifacts under `workspace/strict-reproduction/seven-bench-eval-repair-20261028-r1` and preserves previous viewer receipts there. Future jobs use `QUEST_JUDGMENTS_ROOT` when set. The source run remains `seven-bench-three-4b-flash-20261028-r1`.

The 2026-10-28 three-GPU setup uses ports 18600–18602 for unfinished cases. The controllers reload completed states and receipts; a lost observer is marked interrupted rather than silently restarted, because a fresh rollout is not a continuation of its previous trajectory. `evaluation/reconcile_run.py RUN_ROOT --backup BACKUP_DIR` reconciles dead observers and backs up old status files. It does not start model servers or inference.

Mind2Web2 needs the Playwright Python package matching the installed Chromium revision. The current isolated install is `eval-assets/browser-python` with Playwright 1.64.0 and Chromium revision 1248; its path is added ahead of the shared dependencies by `score_case.py`. Browser processes run headlessly.

BrowseComp and HLE detailed results use `null` for an unavailable ground truth or unparseable judge response. The shared `result_summary.py` reports an unscored count and leaves accuracy null when the denominator contains unresolved judgments. This does not change either benchmark's answer-matching prompt.

FACT citation fetching accepts comma-separated `JINA_API_KEYS` (with `JINA_API_KEY` as a single-key fallback). On HTTP 402 it first tries the remaining configured keys, then uses the shared `api_key_pool.json` Jina pool. Pool choices and 402 exhaustion are synchronized across processes with the same lock and state file as the inference adapter. If all keys fail, retrieval is unavailable. Account-level balances may be shared between keys. Existing failed scrape artifacts should be re-evaluated in a fresh output directory, because the official scraper resumes completed report IDs from its existing JSONL file.

BrowseComp+ uses `browsecomp_plus/quest_adapter.py` to recover numeric `bm25://` IDs from actual search tool responses. Complete observer event logs can establish recall; a retained, potentially compacted message history is labeled `partial_retrieval` and never treated as complete recall. Citation IDs continue to be parsed from the original answer with the official extractor. The scorer loads the checked-in official qrels using an absolute path, and future fixed-corpus prompts ask the model to cite retrieved IDs. Its answer judge uses the upstream BrowseComp+ prompt; the `--chat-completions` transport permits the current OpenAI-compatible DeepSeek endpoint while recording the actual judge model. Prior runs used a different ABC prompt, so their original artifacts are backed up separately.

Both BrowseComp+ scoring entry points leave missing evidence, invalid judgments and insufficient calibration data unavailable instead of manufacturing zeros. Their calibration bin loops include the last bin; judge failures are preserved as unscored items. The official citation parser's bracketed-number convention remains unchanged and can match non-citation bracketed numbers, so inspect citation spans when necessary. `browsecomp-plus-eval-repair-20261028-r1` contains the repaired historical artifacts and backups.
