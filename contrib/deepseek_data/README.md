# DeepSeek data-pipeline adapters (experimental)

Opt in with `QUEST_DEEPSEEK_COMPAT=1` for DeepSeek request parameters and DSML normalization in supported generation/evaluation entry points. `QUEST_DEEPSEEK_TEACHER=1` separately selects the DeepSeek teacher in inference. Credentials are supplied through environment variables and are never included in this directory.

`score_openended.py` requires an independently prepared candidate, reference and criteria, freezes the exact input bytes in a private per-output `.inputs` directory, and refuses empty or failed answers. It validates each rubric criterion and recomputes weighted totals from the recorded per-criterion scores; timeout, malformed or incomplete result coverage, inconsistent totals, and zero denominator are unsuccessful. Partial output, frozen inputs, and logs are retained. `build_openended_ledger.py` requires an explicitly complete single-result score manifest, matching input and score-output hashes, candidate/reference question prefixes, and matching iteration; `export_sft.py` requires scored examples, rejects duplicate task/rollout records, and applies objective/open-ended thresholds. The `independent_agent` flag is a caller declaration and does not itself prove reference independence. `deepseek_judge.py` translates structured Pydantic output into validated JSON. These components are not a complete data-generation controller: objective verifier execution, feedback-based retries, citation backfilling and end-to-end export have not been validated. Do not execute generated Python outside an actually isolated sandbox.

The experiment that informed these adapters rejected two objective tasks and retained zero SFT sessions. A reference-agent failure previously yielded a misleading score; failed or missing reference results must never be used as training acceptance.

Old score status files that lack an output hash cannot establish that the scored output was unchanged and are rejected by the ledger. They remain untouched historical evidence; do not fabricate a score-time hash after the fact.

`continue_reference.py` makes the historical tool-budget continuation reusable with explicit input and new trace/output paths. It records the source hash, request and response in private files, requires an untruncated response, and labels the resulting reference provisional. It is not an independent completed agent run; the ledger rejects attempts to declare such a continuation independent. This command calls the model only when explicitly invoked; it does not establish factual correctness.

Objective rows are excluded from this experimental exporter even if a caller supplies a perfect score: a verified execution, rubric coverage and provenance contract has not yet been established. The manifest records `objective_verifier_unverified`; historic results and the official released SFT data are unaffected.
